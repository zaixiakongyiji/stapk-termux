# Gate 3 代码审查修复计划

根据代码审查子 Agent 的反馈，我们需要对刚刚完成的 Gate 3 代码进行一系列修复。

## 关于 Target SDK 28 的重要决定（请确认）

**子 Agent 的观点**：强烈建议将 `targetSdk` 恢复为 `34`，指出降级到 `28` 是为了绕过 Android 10+ 的 W^X 限制（禁止执行 `filesDir` 等数据目录下的二进制文件），并认为这会引发架构隐患。

**我的技术评估**：由于我们的核心目标是利用 **Termux** 环境（Termux App 本身就是通过保持 `targetSdk=28` 来维持环境运行，从而在 F-Droid 上分发的），在 POC 中使用 `28` 是**合理且必要**的。如果强行升到 34，我们需要将 node 以及后续的 bash, git 等全部伪装成 `libxxx.so` 并通过系统 JNI 库提取机制来加载。这对于当前的 POC 阶段代价太大，且偏离了复用 Termux Bootstrap 的核心设计。

👉 **请您确认**：我们是否驳回子 Agent 关于 `targetSdk=34` 的建议，继续维持 `targetSdk=28`？

## 其他修复内容 (Proposed Changes)

### 1. 补齐缺失的 WebView 实现
目前代码偏离了计划，使用了外部浏览器。
- **修改 `activity_main.xml`**：加入 `<WebView>` 控件，占据界面剩余空间。
- **新建 `TavernWebViewClient.kt`**：创建一个简单的 WebViewClient 实现，处理页面加载。
- **修改 `MainActivity.kt`**：移除唤起外部浏览器的 `Intent.ACTION_VIEW` 逻辑，在轮询 `pollServer` 成功后，调用内部 WebView 的 `loadUrl("http://127.0.0.1:8000")`。

### 2. 修复轮询阻塞和日志吞没
- **修改 `MainActivity.kt`**：修复 `pollServer` 阻塞 `SingleThreadExecutor` 的问题，将其放入独立的 `Thread` 或新建一个专用的线程执行，防止轮询的 10 秒内阻塞其他的按钮点击事件（如 "Run Node"）。
- **修改 `MainActivity.kt`**：在 `pollServer` 捕获异常时增加 `Log.v(TAG, "Poll failed: ${e.message}")` 以协助排查。
